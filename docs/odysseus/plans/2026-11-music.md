# Plan: Music page (Music Assistant on the Echo and tablets)

Written 2026-11-07. A native **Music page** on the home screen of odysseus-echo (Echo Show 5
and Android tablets, same app): what's playing in each room, volume, play/pause, move music
between rooms, group rooms, browse and search the library, and play anything here or in
another room. Same way of working as the earlier plans: one phase is one Claude Code
session, in one repo, with one PR. Each brief stands on its own; where it says
`[paste Cn]` or `[paste In]`, paste that section from "Contracts" below (or point a session
that has this repo at this file).

Repos:
- **echo**: `SDarioosh/odysseus-echo` (default branch `odysseus`)
- **hub**: `SDarioosh/odysseus-expanded` (default branch `barvis`)
- Athena: no changes.

Numbering continues the earlier plans: contracts C7–C8, hub phases H7–H8, echo phases
E10–E15, verification V2. `I1`–`I3` are echo-internal contracts (Kotlin interfaces) that
let echo phases run at the same time.

## What exists today

- Every Echo is a **Sendspin player** in Music Assistant (MA): encrypted, paired, works over
  Tailscale. The clock and the dashboard overlay show its now playing (title, artist, pushed
  artwork) with transport buttons. Those buttons reach only the group this device plays in.
- The app holds a **Home Assistant (HA) token** (admin, from the phone setup) and calls HA
  REST (`WeatherClient`: `POST /api/template`, services with `?return_response`). There's no
  generic HA client and no HA websocket.
- The home screen takes N pages (`HomePages.all`, `HomeNavigator` is generic); pages left of
  the clock aren't possible, and pages can't use horizontal gestures (`HomeHost` owns them).
- The hub has no music code. HA's own intents run before Odysseus (`prefer_local_intents`),
  and HA 2025.6+ handles "play X in the kitchen" for MA players itself (`HassMediaSearchAndPlay`).

## Decisions (change them before starting if you disagree)

1. **The device talks to MA through Home Assistant, never to MA directly.** HA's MA
   integration has everything the page needs (below), the device already has a HA token,
   and HA is reachable over Tailscale where MA's LAN address isn't. No MA token on devices.
2. **One HA websocket while the Music page is visible**, `subscribe_entities` on the MA
   players, for live state; actions over the same socket (`call_service`,
   `return_response`). Closed when the page is hidden or the screen blanks; REST polling is
   the fallback. The rest of the app keeps using REST.
3. **Behind interfaces, so it can grow.** The page talks to a `MusicBackend` (I2), not to
   HA. Another backend later (MA's own API via the hub, for the full queue; a radio-only
   backend; …) is a new class, not a rewrite. Library sections are data (a list of media
   types), so adding podcasts or audiobooks is one line.
4. **Library thumbnails come through the hub** (C8). HA proxies the now-playing art
   (`entity_picture`) but not library or search thumbnails: those point at MA's
   `imageproxy` on its LAN address, or at a streaming service's image CDN. The hub runs
   next to MA, so it fetches them for the device. The device itself never loads images from
   the internet. Whether the hub may fetch CDN images (Spotify art and so on) is the
   owner's call (`FORK_MUSIC_IMAGES_INTERNET`, default **on**: it reveals only cover art
   fetches to a service MA already streams from). Off: those items show a placeholder.
5. **The queue shows now, next and the count** (HA's `get_queue`). The full list isn't
   available through HA; it's a later backend (open question 2).
6. **This device's own player is found by id, not by name** (I3): MA's player id is the
   Sendspin client id the app already has, and HA uses it as the device identifier. "Play
   here" needs no setup.
7. **No hub voice work until it's shown to be needed.** HA's local intents already play,
   pause, skip and set volume on MA players by room and by "here". V2 tries the phrases
   first; H8 only covers what HA misses.
8. **Lock mode applies.** Every play, transfer, volume and group action checks
   `LockMode.isLocked`; the page is under `LockOverlay` like the rest.

## Contracts

### I1 (echo). Home Assistant client: `odysseus/ha/`

```kotlin
package com.msp1974.vacompanion.odysseus.ha

data class HaState(
    val entityId: String,
    val state: String,                  // "playing", "paused", "idle", "off", "unavailable", …
    val attributes: JsonObject,
    val lastUpdatedMs: Long,
)

class HaException(message: String, val code: Int = 0) : Exception(message)

interface HaApi {
    /** POST /api/template (admin token). Never put user text in a template. */
    suspend fun template(template: String): String
    /** A service call. With [returnResponse] the `service_response` (REST) / `response` (ws). */
    suspend fun call(domain: String, service: String, data: JsonObject,
                     returnResponse: Boolean = false): JsonElement?
    /** GET /api/states, filtered. */
    suspend fun states(filter: (HaState) -> Boolean = { true }): List<HaState>
    /** Live states of [entityIds] (websocket subscribe_entities; REST polling every 5 s
     *  as the fallback). Hot while collected; closes the socket when nobody collects. */
    fun watch(entityIds: Set<String>): Flow<Map<String, HaState>>
    /** GET of a HA path with the bearer header (e.g. /api/media_player_proxy/…), ≤ 8 MB. */
    suspend fun bytes(path: String): ByteArray
}
```

- Token and URL from `AuthenticationManager` (`ensureValidSession()`, `getBaseUrl()`), as
  `WeatherRepository` does; one retry with `ensureValidSession(forceRefresh = true)` on 401.
  At most one 401 retry per call (repeated 401s count toward HA's IP ban).
- `HaHttp`/`HaResponse`/`UrlConnectionHaHttp` move from `HaSetupClient.kt` to
  `odysseus/ha/HaHttp.kt` (fork files; same names, so callers only change imports). The body
  cap becomes a parameter (256 KB stays the default; the music calls use 2 MB).
- Websocket: `auth_required` → `{"type":"auth","access_token":…}` → `auth_ok`; then
  `subscribe_entities` (compressed: `a` added, `c` changes with `+`/`-`, `r` removed) and
  `call_service` with `return_response`; `ping` every 30 s; reconnect with 1, 2, 4 … 30 s.
  The decoding of `subscribe_entities` messages is a pure, tested function.
- `HaApi` is the one way new code reaches HA. `WeatherClient` may move onto it later; not
  in these phases.

### I2 (echo). Music domain: `odysseus/music/`

```kotlin
package com.msp1974.vacompanion.odysseus.music

enum class MediaKind { TRACK, ALBUM, ARTIST, PLAYLIST, RADIO, PODCAST, AUDIOBOOK }
enum class Enqueue { PLAY, NEXT, ADD, REPLACE }          // MA: play, next, add, replace
enum class Repeat { OFF, ONE, ALL }

data class MediaItem(val uri: String, val kind: MediaKind, val name: String,
                     val subtitle: String,                // artists, or album/owner
                     val imageUrl: String?, val favorite: Boolean = false)

data class Room(val entityId: String, val name: String, val area: String?,
                val isThisDevice: Boolean, val isGroup: Boolean,
                val groupMembers: List<String>, val available: Boolean)

data class PlayerState(                                   // neutral; I3's UI takes this
    val title: String?, val artist: String?, val album: String?,
    val artUrl: String?,                                   // a HA path or the hub's C8 URL
    val artwork: Bitmap? = null,                           // pushed (Sendspin)
    val playing: Boolean, val durationS: Double?, val positionS: Double?,
    val positionAtMs: Long, val shuffle: Boolean, val repeat: Repeat,
    val volume: Float?, val muted: Boolean, val can: Set<Control>,
) { fun positionNow(nowMs: Long): Double? }

enum class Control { PLAY, PAUSE, NEXT, PREVIOUS, SEEK, SHUFFLE, REPEAT, VOLUME, MUTE, GROUP }

data class QueueSummary(val current: MediaItem?, val next: MediaItem?, val count: Int)
data class LibraryPage(val items: List<MediaItem>, val offset: Int, val hasMore: Boolean)
enum class LibraryOrder { NAME, RECENT, ADDED, MOST_PLAYED, RANDOM }

interface MusicBackend {
    val rooms: StateFlow<List<Room>>                       // live while collected
    fun player(entityId: String): Flow<PlayerState>       // live
    suspend fun queue(entityId: String): QueueSummary?     // null: not an MA queue
    suspend fun library(kind: MediaKind, order: LibraryOrder, favoritesOnly: Boolean,
                        offset: Int, limit: Int = 50): LibraryPage
    suspend fun search(text: String, kinds: Set<MediaKind>, limit: Int = 10): Map<MediaKind, List<MediaItem>>
    suspend fun play(item: MediaItem, roomId: String, enqueue: Enqueue, radio: Boolean = false)
    suspend fun control(roomId: String, control: Control, value: Any? = null) // seek s, volume 0..1, …
    suspend fun transfer(fromRoomId: String, toRoomId: String)
    suspend fun group(leaderId: String, memberIds: List<String>)
    suspend fun ungroup(roomId: String)
}
```

`HaMusicBackend(ha: HaApi, selfClientId: () -> String?, area: () -> String?)` implements it
with:

| Backend call | Home Assistant |
|---|---|
| rooms | template below (once a minute and on change), then `watch()` on the ids |
| player | `watch()` attributes: `media_title`, `media_artist`, `media_album_name`, `media_duration`, `media_position`, `media_position_updated_at`, `shuffle`, `repeat`, `volume_level`, `is_volume_muted`, `entity_picture_local` ?: `entity_picture`, `supported_features` |
| queue | `music_assistant.get_queue` (`return_response`; keyed by entity id; error "No active queue" → null) |
| library | `music_assistant.get_library` `{config_entry_id, media_type, order_by, favorite, offset, limit}` |
| search | `music_assistant.search` `{config_entry_id, name, media_type: [...], limit}` |
| play | `music_assistant.play_media` `{media_id: uri, media_type, enqueue, radio_mode}` on the room |
| control | `media_player.media_play`/`media_pause`/`media_next_track`/`media_previous_track`/`media_seek`/`shuffle_set`/`repeat_set`/`volume_set`/`volume_mute` |
| transfer | `music_assistant.transfer_queue` target = to, `source_player` = from, `auto_play: true` |
| group / ungroup | `media_player.join` (`group_members`) / `media_player.unjoin` |

```jinja
{% set ns = namespace(r=[]) %}
```

### I3 (echo). Which room is this device

A pure function in `odysseus/music/SelfPlayer.kt`, unit-tested:

```kotlin
data class Candidate(val entityId: String, val ids: List<List<String>>, val name: String,
                     val area: String, val type: String?, val available: Boolean)
enum class How { OVERRIDE, ID, LEGACY_ID, NAME, AREA }
data class SelfMatch(val entityId: String, val how: How, val staleOverride: Boolean = false)

fun matchSelf(clientId: String?, uuid: String, area: String?, override: String?,
              candidates: List<Candidate>): SelfMatch?
```

Rules in order:
0. `override` (on-device setting "This device's player") if it is still a candidate; if it
   isn't, carry on and report `staleOverride`.
1. **ID**: a candidate whose ids contain `["music_assistant", clientId]`
   (`SendspinSecurity.state.clientId`; MA's player id is the Sendspin client id). The normal case.
2. **LEGACY_ID**: ids contain `["music_assistant", "vaca-<uuid>"]` (before the key-derived
   id), only if available.
3. **NAME**: exactly one candidate named `VACA <uuid> Sendspin Player` (any case).
4. **AREA**: exactly one candidate of type `player` in `area` (`config.area`, pushed by the
   VACA integration). Shown as a guess ("Kitchen speaker?").
5. Otherwise `null`: no "Play here"; the room picker offers to set the override.

The room picker's default is this device's room, else the first room in `config.area`, else
the last room used.

### C8. Library images through the hub

```
GET /api/chat/voice/v1/music/image?u=<url>&size=<64..512, default 256>     (scope voice)
-> 200 image/jpeg|png|webp, Cache-Control: max-age=604800
   404 {"error": "not found"}   400 {"error": "bad url"}   403 {"error": "not allowed"}
```

- The hub fetches `u` only if it is (a) MA's `imageproxy` on the configured MA base URL
  (`FORK_MA_URL`, e.g. `http://192.168.1.20:8095`; both `imageproxy/<id>` and the older
  `imageproxy?path=…&provider=…` forms), or (b) a public `https` URL while
  `FORK_MUSIC_IMAGES_INTERNET` is on (default on). Never a private, loopback or link-local
  address other than MA's (SSRF guard, checked after DNS resolution), no redirects to them.
- Only `image/*` responses up to 5 MB; scaled down to `size` (longest side) and cached on
  disk under `<DATA_DIR>/music_images/` (sha256 of `u` + size), 7 days, 200 MB cap, oldest
  out first.
- Logs: status and size only, never the URL's query.
- No `FORK_MA_URL` → (a) is off; (b) still works.
